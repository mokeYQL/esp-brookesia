![[Pasted image 20251204170130.png]]# EXAMPLE_SHOW_MEM_INFO = true 日志详解

当 `EXAMPLE_SHOW_MEM_INFO` 设置为 `true` 时，系统会定期输出内存使用情况和任务运行状态信息，用于调试和性能分析。以下是对每个参数的详细解释：

## 1. ESP Memory Info (内存信息)

| 参数       | 解释                                                                 |
|------------|----------------------------------------------------------------------|
| **Biggest** | 最大连续可用内存块大小（字节），表示当前可分配的最大单块内存         |
| **Free**    | 可用内存总量（字节），表示当前所有可分配内存的总和                 |
| **Total**   | 内存总大小（字节），表示该类型内存的总容量                         |
| **SRAM**    | 静态随机访问内存（内部 RAM），用于存放程序代码和核心数据           |
| **PSRAM**   | 伪静态随机访问内存（外部扩展 RAM），用于存放大型数据和资源          |

### 示例解析：
```
ESP Memory Info: 
           Biggest /     Free /    Total 
  SRAM : [  122880 /   218711 /   352571] 
 PSRAM : [11272192 / 11396664 / 12090944]
```
- **SRAM**：总大小 352,571 字节，可用 218,711 字节，最大连续块 122,880 字节
- **PSRAM**：总大小 12,090,944 字节，可用 11,396,664 字节，最大连续块 11,272,192 字节

## 2. AUDIO_SYS 任务信息

| 参数         | 解释                                                                 |
|--------------|----------------------------------------------------------------------|
| **Task**     | 任务名称，标识系统中运行的各个任务                                   |
| **Run Time** | 任务运行时间（毫秒），表示该任务从启动到现在的累计运行时间           |
| **Per**      | 任务 CPU 占用率（百分比），表示该任务占用 CPU 时间的比例             |
| **Prio**     | 任务优先级，数值越大优先级越高（0-24）                              |
| **HWM**      | 任务栈历史最高使用量（字节），表示该任务曾经使用的最大栈空间         |
| **State**    | 任务当前状态（Ready: 就绪, Blocked: 阻塞, Suspended: 挂起）          |
| **CoreId**   | 任务运行的 CPU 核心 ID（0 或 1，7fffffff 表示未绑定）               |
| **Stack**    | 任务栈类型（Intr: 内部 RAM, Extr: 外部 PSRAM）                     |

### 示例解析：
```
I (88003) AUDIO_SYS: | Task              | Run Time    | Per | Prio | HWM       | State   | CoreId   | Stack 
I (88004) AUDIO_SYS: | IDLE0             | 995030      |49%  | 0    | 724       | Ready   | 0        | Intr 
I (88004) AUDIO_SYS: | ipc0              | 0           | 0%  | 1    | 468       | Suspended | 0        | Intr 
I (88004) AUDIO_SYS: | http              | 0           | 0%  | 10   | 4136      | Blocked | 0        | Extr 
```

#### 关键任务说明：
- **IDLE0/IDLE1**：CPU 空闲任务，优先级最低（0），占用率约 49% 表示 CPU 利用率较低
- **ipc0/ipc1**：CPU 间通信任务，用于核心间数据传输
- **esp_timer**：系统定时器任务，用于处理定时事件
- **taskLVGL**：LVGL 主任务，负责 UI 渲染和事件处理
- **lvglDraw**：LVGL 绘制任务，负责实际的图形绘制操作
- **storage_nvs**：NVS 存储服务任务
- **mem_info**：内存信息打印任务（当前正在运行）
- **Tmr Svc**：FreeRTOS 定时器服务任务

## 3. 如何使用这些信息

### 内存优化：
- **SRAM Biggest** 较小：表示内存碎片较多，可能需要优化内存分配策略
- **PSRAM Free** 不足：表示外部内存使用过多，可能需要减少大型资源加载
- **SRAM Free** 不足：表示内部内存紧张，可能需要将部分数据移至 PSRAM

### 性能优化：
- **Task Per** 过高：表示该任务占用 CPU 过多，可能需要优化算法或降低优先级
- **Task HWM** 接近栈大小：表示该任务栈空间不足，可能需要增大栈大小
- **Task Run Time** 异常：表示任务可能存在死循环或阻塞问题

### 调试用途：
- **Task State**：判断任务是否正常运行
- **CoreId**：查看任务的 CPU 核心分配情况
- **Stack**：确认任务使用的内存类型

## 4. 配置建议

- **开发阶段**：建议将 `EXAMPLE_SHOW_MEM_INFO` 设置为 `true`，便于调试和性能分析
- **生产阶段**：建议将 `EXAMPLE_SHOW_MEM_INFO` 设置为 `false`，减少日志输出，降低系统开销
- **内存密集型应用**：可以调整内存信息打印的时间间隔，避免频繁打印影响性能

通过分析这些日志信息，可以帮助开发者：
1. 识别内存泄漏和内存碎片问题
2. 优化任务优先级和 CPU 资源分配
3. 调整栈大小和内存分配策略
4. 定位性能瓶颈和异常任务

这对于开发稳定、高效的 ESP-Brookesia 应用非常重要，尤其是在资源受限的嵌入式设备上。
