## 项目概述

在 `Replica_ai` 项目中实现了基于 ESP-Coze 组件的 AI 对话功能，通过 Coze API 实现智能语音对话交互。参考了 `brookesia_core` 组件中的 `ai_framework` 实现模式。

## 新增文件结构

```
Replica_ai/main/modules/
├── ai_chat.cpp          # AI 对话核心实现（757行）
├── ai_chat.hpp          # AI 对话接口定义（128行）
├── wifi_connect.c       # WiFi 连接 + SNTP 时间同步（335行）
```

### 文件说明

#### 1. `ai_chat.hpp` - AI 对话接口层
定义了完整的 AI 对话 API 接口，包括：
- 事件类型枚举（9种事件）
- 事件回调函数类型
- 初始化/反初始化接口
- 启动/停止/暂停/恢复接口
- 唤醒/睡眠/中断接口

#### 2. `ai_chat.cpp` - AI 对话实现层
实现了完整的 AI 对话功能，核心模块包括：
- **Coze OAuth 认证**（`coze_get_access_token`）
- **JWT Token 生成**（使用私钥签名）
- **WebSocket 对话管理**（通过 `esp_coze_chat` 组件）
- **事件回调系统**
- **音频数据处理**

#### 3. `wifi_connect.c/h` - 网络基础设施
提供 WiFi 连接和 SNTP 时间同步功能：
- WiFi 连接管理（自动重连）
- SNTP 时间同步（使用阿里云 NTP 服务器）
- 事件驱动架构

## 技术要点

### 1. **Coze OAuth 认证流程**

```
┌─────────────┐    JWT Token    ┌──────────────┐    HTTP POST    ┌──────────┐
│   ESP32     │ ──────────────> │   Coze API   │ ──────────────> │ Coze API │
│             │                 │              │                 │          │
└─────────────┘                 └──────────────┘                 └──────────┘
     ↓                               ↓                                ↓
  生成 JWT                         JWT 签名                       返回 Token
  (带时间戳)                     (RSA 私钥)                     (访问令牌)
```

**关键代码 (`ai_chat.cpp:120-283`)：**

```cpp
// 构建 JWT payload
cJSON *payload_json = cJSON_CreateObject();
time_t now = time(NULL);
cJSON_AddStringToObject(payload_json, "iss", COZE_APP_ID);
cJSON_AddStringToObject(payload_json, "aud", "api.coze.cn");
cJSON_AddNumberToObject(payload_json, "iat", now);          // 签发时间
cJSON_AddNumberToObject(payload_json, "exp", now + 6000);    // 过期时间
cJSON_AddStringToObject(payload_json, "jti", random_str);   // 唯一标识

// 使用 RSA 私钥签名 JWT
char *jwt = coze_jwt_create_handler(COZE_PUBLIC_KEY, payload_str,
                                    (const uint8_t *)private_key, private_key_size);

// 使用 JWT 获取 Access Token
char *authorization = sprintf("Bearer %s", jwt);
http_client_post(coze_authorization_url, header, http_req_json_str, &response);
```

### 2. **SNTP 时间同步（关键！）**

**为什么需要时间同步？**
- JWT Token 依赖 `iat`（签发时间）和 `exp`（过期时间）字段
- ESP32 默认时间从 1970 年开始，必须通过 SNTP 同步网络时间
- 否则 Coze API 会拒绝认证（时间戳无效）

**实现流程 (`wifi_connect.c:239-335`)：**

```c
// 初始化阶段（WiFi 连接前）
esp_sntp_config_t sntp_config = {
    .start = false,              // 不自动启动
    .sync_cb = sntp_sync_callback,
    .servers = {"ntp.aliyun.com"}
};
esp_netif_sntp_init(&sntp_config);

// 启动阶段（WiFi 连接后）
esp_netif_sntp_start();
esp_netif_sntp_sync_wait(2000 / portTICK_PERIOD_MS);  // 等待同步完成
```

### 3. **WiFi 连接管理**

```c
static void wifi_event_handler(...) {
    if (event_id == WIFI_EVENT_STA_DISCONNECTED) {
        if (s_retry_num < MAX_RETRY) {
            esp_wifi_connect();
            s_retry_num++;
        }
    } else if (event_id == IP_EVENT_STA_GOT_IP) {
        xEventGroupSetBits(s_wifi_event_group, WIFI_CONNECTED_BIT);
```

```c
}

// 等待同步完成
```

## 关键问题和解决方案

### 问题 1: JWT Token 时间戳无效（1970 epoch）

**现象：**
```
❌ JWT Payload: {"iss":"1118995002061","iat":909,"exp":6909,...}
❌ HTTP Response: {"error":"invalid_token","message":"Token expired"}
```

**原因：**
- ESP32 默认时间从 1970 年开始
- JWT 的 `iat` 和 `exp` 字段使用 Unix 时间戳
- Coze API 验证时间戳时发现已过期

**解决方案：**
在获取 Access Token 之前必须进行 SNTP 时间同步：

```cpp
// WiFi 连接完成后
wifi_sync_time_init();           // 初始化 SNTP
wifi_sync_time_start(60000);      // 启动并等待同步

// 验证时间已同步
time_t now = time(NULL);
assert(now > 1700000000);        // 确保时间在 2023 年之后
```

### 问题 2: SNTP 同步超时

**现象：**
```
E (62714) WIFI_CONNECT: ❌ 时间同步超时
```

**原因：**
- 使用了错误的等待方式（手动检查时间变化）
- 没有正确调用 `esp_netif_sntp_sync_wait()`

**解决方案：**
参考源项目 `app_sntp.c` 的实现：

```c
// 错误做法：手动检查时间变化
while (retry < retry_count) {
    time_t delta = time(NULL) - before;
    if (delta > 100) break;  // 不稳定！
}

// 正确做法：使用同步等待 API
while (esp_netif_sntp_sync_wait(2000 / portTICK_PERIOD_MS) == ESP_ERR_TIMEOUT) {
    retry++;
    if (retry >= retry_count_max) return ESP_ERR_TIMEOUT;
}
```
